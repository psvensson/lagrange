### Accidental identity sharing
Identity is (node_id, boot_incarnation). The value `1` (419 lines) is safe across different node ids. The risk is one node id constructed twice with the same incarnation inside one scenario sharing durable state (a restart that production would give a new incarnation). `incarnation-sharing.mjs` groups every NodeJoiningService/BootstrapService construction by (file, literal nodeId, incarnation). 17 groups repeat. By inspection each repetition is in a separate `test(...)` with its own store/seed, so no scenario models a restart with a reused incarnation:
bootstrap-sequence (7), cache-hydration-correctness.property (5), cdc-propagation-message-group-selection (4+5), dynamic-partition-cdc-subscription (4+5), join-startup-owner-routing (3), latency-topology-owner-delegation (2+2), node-joining-cdc-readiness-gate-signal (4), node-joining-cdc-subscription (6), node-joining-control-plane-heartbeat (8), node-joining-service-message-group-activation (2), node-joining-service test-node-1 (2) and durable-join-node (6), node-ready-rebalance-trigger (18), runtime-startup-wiring (2).
The durable-rejoin scenarios in node-joining-service.test.js seed NODES rows without boot_incarnation (legacy 0), so the rejoining process (1) is strictly newer. That is the advance path, not sharing. The dedicated incarnation tests use distinct values (PREVIOUS_BOOT / THIS_BOOT / THIS_BOOT + 1, G1/G2, 2..9).
