# Epic: Steering-doc clarity remediation

**Intent:** Resolve the 17 audited issues that would confuse an LLM agent reading
the steering corpus (contradictions, vocab-before-definition, pack-truncation
framing, dangling refs, reworded duplicates). Source: steering-doc audit,
2026-06-17.

**Hard constraint (routing):** Generated packs (`.kiro/steering/llm/{architecture,
testing,style,governance}.md`, `rules-index.md`, `rules.json`, `manifest.json`)
MUST NOT be hand-edited — `npm run steering:check` regenerates them and asserts
`git diff --quiet`, so direct edits are reverted/flagged. Pack content changes go
through (a) the source steering file, (b) `llm-pack.config.json`, or (c) the
generator `scripts/generate-steering-llm-pack.js`. Manual packs `core.md`,
`boot.md`, `README.md` are edited directly. After any source/config/generator
change: `npm run steering:llm:pack` then confirm `npm run steering:check` is green.

**Routing legend per edit:** MANUAL = edit file directly · SOURCE = edit source +
regen · CONFIG = edit `llm-pack.config.json` + regen · GEN = edit generator script
+ regen · DOC = plain doc, no regen.

## Work packages

### WP-A — Pack-completeness framing  (Finding #1, highest impact)
Packs are priority-capped subsets (ARCH 40/103, TEST 35/72, GOV 30/88) but are
described as "the canonical execution-time surface," so an agent treats a pack as
complete and silently misses 60%+ of rules (e.g. GOV-0069 absent from the pack).
Caps are intentional; the fix is honest labeling.
- **GEN** `scripts/generate-steering-llm-pack.js`: emit a header line in each
  generated domain pack — e.g. `> Top {emitted} of {domainTotal} {domain} rules by
  priority. Full corpus: rules-index.md or \`npm run rule\`.` (compute
  `domainTotal` = domain rule count before the cap).
- **GEN** (NOT manual) `README.md` is fully regenerated by `renderReadme()`
  (generator ~line 1097) on every pack run — its `status: manual-pack` frontmatter
  is misleading. Change "canonical execution-time surface" → "always-loaded
  priority subset; consult `rules-index.md` / `npm run rule` for the full corpus"
  IN `renderReadme()`, and correct the misleading frontmatter there too. A direct
  edit to README.md is clobbered and fails `steering:check`.
- **MANUAL** `AGENTS.md:72`: change "default LLM execution surface" likewise
  (AGENTS.md is not generated).
- Verify: each regenerated pack shows the header; counts match `manifest.json`.

### WP-B — Vocabulary before definition  (Finding #2)
`core.md` (read first per AGENTS load order) uses frontier/doneWhen/EXHAUSTED/owner
15× with no glossary; definitions live in `boot.md` (read second) and at the bottom
of the 41 KB `solver-quests.md`. Also undefined on first use: park, owner, sealed,
proof ladder, subagent, probe, and gate states MAX_CYCLES/THEORY_REQUIRED/BLOCKED.
- **MANUAL** Establish ONE canonical glossary to avoid drift. Recommendation:
  put the compact glossary in `core.md` (always-load, read first); `boot.md`
  keeps the Quest-vocabulary table only if it forward-references core.md as
  canonical, otherwise replace boot's table with a pointer. Glossary must cover
  the terms above incl. the three gate states.
- **SOURCE** `workflow-guidelines/solver-quests.md`: hoist the "User-Facing
  Vocabulary" section to the top (before first use, ~line 27). Vocabulary lines
  are non-normative (no MUST/SHOULD/NEVER) so should not change generated rules.
- **ID-STABILITY GUARD (applies to WP-B and WP-D):** rule IDs are positional —
  `assignRuleIds` ranks each domain by score then assigns `PREFIX-NNNN` by rank.
  Inserting/removing a normative line, or rewording one enough to change its
  score, can **renumber GOV IDs below it**, and GOV numbers are cited by number in
  `solve/report/autonomy-and-parallel-defaults.md`, `docs/*-plan.md`, and this
  epic. After regen, assert the GOV id→text map is unchanged for untouched rules;
  if any ID remaps, update the citing docs in the same change.
- **VALIDATOR CONSTRAINT:** `validateRulesHaveTriggerAndCitation` throws on
  admonition / all-caps-label / dangling-pronoun openers. Reworded normative
  sentences must not start with a bare ALL-CAPS label, "STOP", "They/This must…",
  or an em-dash label, or `steering:llm:pack` fails.
- Open question for user: glossary single-source = core.md vs boot.md.

### WP-G — Pack-generation hygiene  (Findings #10, #11, #12, #13)
- **#10** `THEORY_REQUIRED` → `THEORYREQUIRED` corruption. **GEN** (root cause):
  `stripInlineMarkdown`'s italic regex `_([^_]+)_` (~generator line 227) pairs the
  underscores in `MAX_CYCLES / THEORY_REQUIRED` and strips them; the single-token
  `**MAX_CYCLES**` survives because it has no pairable underscore. Fix = make the
  stripper snake_case-safe, not per-token source escaping.
- **#11** REVISED after investigation: TEST-0035/0036 are NOT true duplicates —
  they are two distinct remediation steps (`harness.md:58` identify root cause /
  `:59` resolve). The generator prepends the full normative preamble
  (`harness.md:56`) to each child bullet, so each rule body repeats the preamble
  and the rules-index leading-text summary renders them as identical. Fix is a
  design choice (see options below), all with TEST ID-renumbering risk:
  (a) GEN: stop prepending the parent preamble to child-bullet rule bodies —
      systemic, but renumbers child-bullet rules across all domains;
  (b) SOURCE: restructure the `harness.md` duration section so the steps are prose,
      not a normative numbered list — localized to TEST IDs ≥ 0035;
  (c) index-only: make rules-index summaries show a distinguishing tail on
      collision — cosmetic, no renumber, leaves redundant rule bodies;
  (d) accept/defer: they are legitimately distinct; the clash is summary-only.
  **DECISION NEEDED before implementing.**
- **#12** Same/cross-domain reworded duplicates while `ruleAliases: []` is empty.
  **CONFIG** `ruleAliases` is keyed by source `{file, line}`, NOT by rule ID —
  each entry is `{"canonical": {"file","line"}, "aliases": [{"file","line"}]}`
  (the generator's `applyRuleAliases`/`locateRuleBySourceRef` matches source refs;
  ID pairs silently no-op). Pairs to alias (use rules-index to get each rule's
  source file:line): ARCH-0006/STYLE-0003 (synonyms), ARCH-0007/STYLE-0001
  (ordinal filenames), STYLE-0007/TEST-0029 (file-size), ARCH-0026/ARCH-0047
  (degraded evidence — note: both architecture, same-domain; intra-domain
  `semanticDedupe` missed them, ruleAliases is still the right tool). Verify
  aliases gain `canonical_of` and are suppressed from pack emission after regen.
- **#13** "a couple of seconds" → "2s unit / 30s integration", on **both**
  `harness.md:58` (TEST-0035) and `:59` (TEST-0036). **SOURCE** Fold into #11's
  merge so both source lines are corrected.
