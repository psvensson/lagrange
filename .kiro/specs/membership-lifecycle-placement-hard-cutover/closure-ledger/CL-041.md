## LOG (append-only)

### 2026-06-16 — opened + FIX LANDED → `guarded` (found by the raft safety-invariant sweep)

Surfaced by a deliberate raft safety-invariant chaos sweep over the DT6 harness (seeded partition/heal/command sequences over real liferaft clusters, checking Election Safety / Log Matching / committed-entry agreement). The sweep's RAW output was dominated by drive-granularity ARTIFACTS (apparent violations that appeared at coarse `driveNetwork` steps and vanished at fine ones — the async drive can sample a half-settled state; see [[raft-safety-sweep-and-harness-fidelity]]). But triaging the worst case (a follower granting two candidates in one term) led to this REAL race, then isolated to a clean unit repro with no harness involvement.

Mechanism (base liferaft `case 'vote'`):
```
if (raft.votes.for && raft.votes.for !== packet.address) { ...deny... }   // CHECK
if (raft.log) { const {index, term} = await raft.log.getLastInfo(); ... } // AWAIT (log only)
raft.votes.for = packet.address; ...grant...                             // ASSIGN
```
Two concurrent same-term votes both pass CHECK (votes.for null) before either reaches ASSIGN → both granted. Gated by `if (raft.log)`, so it affects the production message-group raft (uses `InMemoryLogAdapter`) but not the logless DT4 scenarios. Real-world frequency is low (election-timer index-jitter staggers candidacies) but non-zero, and the consequence (two leaders in one term) is a split-brain safety violation.

Fix: `src/raft/liferaft.js` `patchIncomingDataListener` serializes `vote` packets through a per-node promise chain (`voteSerializationChain.then(processVote, processVote)`), guarded on `raft.log` so logless nodes keep byte-identical timing (cf. CL-040). The second concurrent vote runs only after the first has recorded `votes.for`, so it correctly denies. Higher-term votes still supersede (a higher term resets `votes.for` via the base preamble's `term change`). Inert on the normal path (single-candidate elections process votes in order). Introduces no new writer / no leadership change → B4 single-writer invariant unaffected.

Evidence: unit repro green/red-on-revert; `test/raft/` 689/689; `test/message-group/` all pass + 3 pre-existing skips; DT6 election + migration 52/52; the chaos sweep's two-leaders + log-matching violations ELIMINATED by this fix (10–12/300 → 0). Subagent-verified TRUSTED.
