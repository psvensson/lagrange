## LOG (append-only)

### 2026-06-16 — opened + FIX LANDED → `guarded` (found by the raft safety-invariant sweep)

Root-caused from the raft safety-invariant sweep's residual committed-divergence (seed 21, n=5), via an independent worktree investigation + a harness-free confirmation. The sweep had shown a STABLE committed-log divergence at a low index that CL-040 (same-index truncation) and CL-041 (double-vote) did not cover. The mechanism is upstream of both: the **empty-log last-term masquerade**.

Mechanism:
- An empty log's `getLastInfo()` returns `term = node.term` (the node's election term), not 0 (`in-memory-log-adapter.js getLastEntry`; `sqlite-log-adapter.js getLastInfo`/`getLastEntry`; mirroring base liferaft `log.js`). Log indices start at 1, so `index===0` ⟺ empty log ⟺ last-log-term 0.
- An isolated node (empty log) that bumps its term via failed elections then advertises `vote.last = {index:0, term:<high>}`. The base up-to-date check (`@markwylde/liferaft index.js:234`) compares advertised last-term: a voter holding committed `{idx,term:1}` sees the candidate's "last term" `<high>` and grants (`1 > high` false). The empty-log candidate wins WITHOUT the committed entry → writes its own command at the same index → two different committed commands at one index. (Confirmed harness-free: a voter with committed `{idx1,term1}` grants an empty-log `term:11` candidate.)
- Why CL-040/CL-041 don't catch it: CL-040 refuses to truncate a *committed* entry (correctly); CL-041 is the double-vote TOCTOU, a different defect. This is the up-to-date *comparison*, fed by the masqueraded last-term.

The masquerade bites BOTH sides: an empty-log CANDIDATE over-advertises (the SAFETY bug — over-grant → divergence), and an empty-log VOTER over-computes its own last-term (a LIVENESS issue — over-denies legitimate candidates; a candidate-side-only wrapper fix made an empty voter deny an empty candidate, breaking cold-start grants — so the fix must be symmetric).

Fix (root, both raft systems): normalize an empty log's last-log-term to 0 in `getLastEntry`/`getLastInfo` of both adapters (`in-memory-log-adapter.js`, `sqlite-log-adapter.js`). This corrects the up-to-date comparison on both sides: an empty candidate never out-ranks a log-bearing voter (closes the safety bug), and an empty voter still grants (preserves cold-start/recovery liveness). Append-path unaffected (an index-0 prevLog is never term-checked — the base append handler skips the consistency check when `packet.last.index === 0`). The wrapper (`src/raft/liferaft.js`) is shared by both the message-group raft (in-memory adapter) and the partition raft (sqlite adapter); fixing both adapters covers both. The base-liferaft `log.js` has the same masquerade but is unused (our raft instances always pass an adapter as `Log`).

Evidence: unit repro green/red-on-revert; the chaos sweep's committed-divergence ELIMINATED (seed 21 clean; 0/70 at max fidelity, was 1/70 — and the broader fine sweep 9–12/300 → 0); `test/raft/` 689/689 (one property test that asserted the old `term==node.term` behavior updated to the correct `term==0`); `test/message-group/` + `test/partition/` + `test/node/` + DT6 + closure all green.
