# CL-039 The Publication Owner Must Be Able To Reach A Live control_plane_publications-p1 Write-Leader To Close An OPEN Epoch (leadership must not strand on a restarting replica with no fail-back)

- Status: OPEN (pinned 2026-06-15 session 2, record-before-code; NO fix yet). Surfaced as the
  surviving non-converged class once the CL-001 variant-C owner-trim was retired (gate
  stat-gate-20260615T085708Z run3, STALLED missing=1).
- Concern: membership-publication write substrate / control-plane raft leadership placement
- Failure Class: convergence-lag (liveness — OPEN publication never closes; no corruption)
- First Violated Invariant: the membership-publication OWNER (the seed) must be — or must be
  able to reach — the `control_plane_publications-p1` Raft WRITE-LEADER so that an OPEN
  publication epoch can advance OPEN → PUBLISHED. control_plane_publications is by design a
  single non-splittable partition = one Raft leader = one authoritative writer (B4 invariant);
  when that single leadership is allowed to land on a node that is then RESTARTED (and whose
  replica handler never re-registers), and there is no fail-back/re-election to a live reachable
  writer, the owner's epoch-advance UPSERT routes to the stranded leader/replicas and fails
  CLOSED on every retry — so the epoch never closes and the already-published node is reported
  "missing" to budget.
- Authoritative Owner: control-plane raft leadership placement for priority partitions +
  the membership-publication coordinator write path.
- Authoritative State: control_plane_publications-p1 raft leadership + the published epoch row.
- Stable Witness: publicationStatus=OPEN with streamOutcome=publishing /
  recoveryOutcome=waiting_for_publication; seed "Failed to upsert system table row"
  (tableName=control_plane_publications, error="Distributed operation failed due to participant
  failures", code=DISTRIBUTED_PARTICIPANT_FAILURE) repeating to teardown; seed NO_HANDLER for the
  partition's restarted replicas.
