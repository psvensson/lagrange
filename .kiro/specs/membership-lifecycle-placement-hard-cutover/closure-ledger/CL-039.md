# CL-039 The Publication Owner Must Be Able To Reach A Live control_plane_publications-p1 Write-Leader To Close An OPEN Epoch (leadership must not strand on a restarting replica with no fail-back)

- Status: OPEN (pinned 2026-06-15 session 2, record-before-code; NO fix yet). Surfaced as the
  surviving non-converged class once the CL-001 variant-C owner-trim was retired (gate
  stat-gate-20260615T085708Z run3, STALLED missing=1).
- Concern: membership-publication write substrate / control-plane raft leadership placement
- Failure Class: convergence-lag (liveness — OPEN publication never closes; no corruption)
- First Violated Invariant: the membership-publication OWNER (the seed) must be — or must be
  able to reach — the `control_plane_publications-p1` Raft WRITE-LEADER so that an OPEN
  publication epoch can advance OPEN → PUBLISHED. control_plane_publications is by design a
  single non-splittable partition = one Raft leader = one authoritative writer (B4 invariant);
  when that single leadership is allowed to land on a node that is then RESTARTED (and whose
  replica handler never re-registers), and there is no fail-back/re-election to a live reachable
  writer, the owner's epoch-advance UPSERT routes to the stranded leader/replicas and fails
  CLOSED on every retry — so the epoch never closes and the already-published node is reported
  "missing" to budget.
- Authoritative Owner: control-plane raft leadership placement for priority partitions +
  the membership-publication coordinator write path.
- Authoritative State: control_plane_publications-p1 raft leadership + the published epoch row.
- Stable Witness: publicationStatus=OPEN with streamOutcome=publishing /
  recoveryOutcome=waiting_for_publication; seed "Failed to upsert system table row"
  (tableName=control_plane_publications, error="Distributed operation failed due to participant
  failures", code=DISTRIBUTED_PARTICIPANT_FAILURE) repeating to teardown; seed NO_HANDLER for the
  partition's restarted replicas.

## FALSIFICATION FINDING 2026-06-15 (lever-selecting research; still record-before-code, NO fix)

Researched existing leadership mechanisms (per "research existing mechanisms first"):
- NO explicit leadership-transfer / preferred-leader / drain-before-stop mechanism exists in src/
  (grep leadership.?transfer|transferLeadership|preferredLeader|stepDownLeader|drainLeadership →
  only a tangential message-group-target-resolver.js hit). The rolling-restart drain does NOT
  transfer partition leadership OFF a node before stopping it.
- The ONLY leadership preference is IMPLICIT via election-timer INDEX JITTER
  (src/raft/constants.js RAFT_ELECTION_TIMING: JITTER_PER_REPLICA_MS=2500 ≥ (MAX−MIN), comment:
  "lower-indexed replicas always fire first ... preventing re-elections and leadership instability").
  control_plane_publications-p1's lowest-indexed replicas r1/r2/r3 are ALL on the stable seed, so
  by design leadership SHOULD prefer the seed.
- WHY IT STRANDED ON 8be8d30f (the crux): the index-preference is DEFEATED BY THE SEED GAP. During
  the seed's 4.26s event-loop gap (09:14:22) the seed's low-index replicas cannot fire/respond to
  their election timers, so a higher-index replica on another node wins the election by default;
  and raft does NOT preempt a stable leader once elected, so leadership never returns to the seed
  even after it recovers. Election timing is ADAPTIVE (config-constants.js: active election timeout
  max 3000ms; idle 3000/5000ms) — the 4.26s gap exceeds the active 3000ms ceiling.

LEVER SELECTION (refined):
- Lever A (seed gap) is the TRIGGER that defeats the existing index-preference. Fully killing a
  4.26s formation-window gap is the CL-034 lineage and may be hard; but raising/adapting the
  control-plane election timeout so a sub-~5s host stall does NOT shed leadership is a smaller,
  targeted variant (RISK: slows genuine failover — bound it to formation/recovery).
- Lever B' (NEW, likely the cleanest correctness fix): add an explicit leadership FAIL-BACK /
  transfer that restores leadership to the stable low-index replica (seed) after a disturbance,
  AND/OR transfer leadership OFF a node before the restart drain stops it (so a restarting node is
  never left holding publications-p1 leadership). Must respect the B4 single-writer invariant
  (one partition = one leader = one writer) — a transfer is safe (still one leader), a parallel
  writer is NOT.
- Lever C (write resilience): when the owner's epoch-advance write fails closed against a
  persistently-unreachable write-leader for N retries, force a leadership transfer/re-election to a
  reachable replica instead of retrying a dead leader to budget.
