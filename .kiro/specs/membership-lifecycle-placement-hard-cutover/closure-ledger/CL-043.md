Implemented Locus-A variant (i): the concurrent-partition-operation gate now ignores a concurrent op
whose configured step timeout has already elapsed.

- **Fix**: `src/rebalancer/operation-workflow-remove-safety-evaluator.js` — the "Concurrent partition
  operation check" `allOps.find(...)` now also requires
  `!context.isConcurrentOperationStalePastStepTimeout(op, context.resolveTimeoutCheckNowMs())`. New thin
  method `isConcurrentOperationStalePastStepTimeout(op, now)` in
  `src/rebalancer/operation-workflow-recovery-timeout.js` delegates to the existing

- **Safety argument** (why relaxing this gate is sound): the concurrent-op gate is a SERIALIZATION guard,

  concurrent-op set. A genuinely in-flight op bumps updatedAt each step and stays within its timeout, so it
  still blocks; an unparseable/zero-timeout op is conservatively still treated as active.
