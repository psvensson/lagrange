## 1. formation-sim-charged-seed-host.test.js: RangeError Map maximum size exceeded

What fills the map: `asyncGenerationIds.set(asyncId, stored.generationId)` in the generation-lineage init hook, src/diagnostics/formation-turn-attribution.js:98-107. Map declared :93; no destroy on purpose (:109-111); the only clear is endGenerationLineage() :115-120 when the generation root exits. runSeedHandoffScenario runs the whole scenario under ONE generation root (test/simulation/formation-sim-production-seed-host.js:760-772), so the map holds one entry per async resource created in the scenario until it ends. V8 Maps refuse the 2^24+1 = 16,777,217th entry. Contrast: the attribution's asyncOwners / asyncExecutionNodes DO delete on destroy (:342-345).

Measured allocation ($I/probe-async-inits.mjs, one charged scenario, all async_hooks inits, 1-in-500 stack samples):

## 4. concurrent-move-replica-assignment.integration.test.js: second request 503

Actual answer ($I/concurrent-scratch.out BODY2; $I/concurrent-timeline-head.out): 503 {"success":false,"error":"Bootstrap not ready","code":"BOOTSTRAP_NOT_READY","reasons":["READINESS_STABLE_WINDOW_PENDING","JOIN_ADMISSION_BACKPRESSURED"],"retryAfterMs":1000,"state":"warming",...}. On head the first handler's reservation write yields to the loop: its non-PROMISE resources ($I/concurrent-macrotask-head.out) include RealTimeSource.setTimeout from scheduleInboundDrain (raft-rs-runtime-owner.js:1225, INBOUND_DRAIN_DELAY_MS = 0, raft-rs-runtime-owner-constants.js:132) reached via enqueueStep (:1338) and the port (raft-rs-operation-port.js:200-205), plus the commit-deadline timer of waitForCommittedWrite (partition-service-cdc-stream-base.js:281).
