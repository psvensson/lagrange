## The helper: `test/test-helpers/committed-write-answer.js`

A double that stands in for a control-plane write producer answers through it; no receipt object is hand-built.
Production code it calls:

| Level | Function | Production code called |
|---|---|---|
| partition leader | `committedPartitionWriteAnswer(entry, effect)` | `PartitionServiceEntryApplyBase.prototype.buildCommittedWriteIdentity` (-> `buildDurableCommitWitness`, `partition-write-kernel.js`) for a fresh commit; `answerSettledStatement` (`partition-committed-statement-outcome.js`) for a settled replay. The only literal is the resolved shape `{success, changes, lastInsertRowid, ...identity}` of `applyCommittedEntry`. |
| engine (`SQLQueryEngine.executeQuery`) | `engineCommittedWriteAnswer(sql, params, options, effect)` | real `SQLParser` (table, statement type); route = `INITIAL_PARTITION_IDS[table]`; real `DistributedWriteCoordinator` `createWritePlan` / `executePlan` / `executePlanParticipants` / `createParticipantExecutionOptions` (entryId = `deriveParticipantEntryId(key, partition)`) over the real `QueryExecutor.prototype.executeInsert / executeUpdate / executeDelete` rendering (`query-executor-sql-command-rendering.js`, incl. `buildDistributedMutationResult`); only the SQL builder (returns the caller's text) and the partition delivery (returns the leader answer above) are stubbed. |
| CDC (`CDCIntegrationService`) | `cdcCommittedWriteAnswer(method, args, effect)` | a real `CDCIntegrationService` instance (per call, shut down after) whose engine answers through `engineCommittedWriteAnswer`; the method (`insert/upsert/update/deleteSystemTableRow`) runs as in production. |

`effect` = the double's storage outcome: `changes` (default 1), `rows`, `lastInsertRowid`, `originHlc` (becomes the
committed command's timestamp, so the producer derives `originHlc`), `settledReplay`, `logIndex`, `term`, `nodeId`,
`replicaId`, `partitionId` (route override).

Pin: `test/test-helpers/committed-write-answer.test.js` — engine INSERT/UPDATE/UPDATE-0-rows/DELETE/settled replay
APPLIED by the real `judgeNamedWriteOutcome` for their own key+partition, UNKNOWN for another key or partition; the real
CDC service's four write methods over the helper APPLIED; the old receipt-less shapes (`{success:true}`,
`{success,affectedRows}`, CDC-wrapped bare engine answer, old insertViaUpsert, heartbeat-liveness shape) UNKNOWN; a named
gateway write (real gateway + real CDC + helper engine) settles in one delivery, twice under the same name.
