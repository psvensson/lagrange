# Ownership map — planning generation / token / completed snapshot (quest readiness-planning-snapshot-liveness)

Traced on e9774db2e. One owner per fact; consumers observe.

| Fact | Owner (module) | How it changes | Who reads it |
| --- | --- | --- | --- |
| Authoritative readiness facts (rows, transport, lifecycle, publication mode) | source owners (system-table cache, router, lifecycle machine, CDC publication) | source mutations; the cache-change listener (`snapshot-store.js handleCacheChange`, fires on `setImmediate`) forwards table changes | `ReadinessPlanningSnapshotOwner.recordTableChange` / `recordCacheReplacement` / `recordOwnerDependencyReplacement` / `recordReadinessSnapshotChange` / `recordRecoveryEpochChange` |
| Planning token (exact generation) | `ReadinessPlanningSnapshotOwner` (`captureToken` → `freezeToken`, `readiness-planning-version-contract.js`) = {cacheGeneration, membershipOwnerGeneration, ownerDependencyGenerations, **tableRevisions per table (exact per write)**, readinessSnapshotGeneration, recoveryEpochRevision, transportTopologyGeneration (router connected-node fingerprint, refreshed on every capture), generationSaturated} | any recorded source change bumps a component (`nextSemanticGeneration`); the transport fingerprint is re-read on every `captureToken` | `readSync` (per read), `enqueueBuild`, `reconcile` (build start), `publishCompleted` (completion) |
| Floored planning generation (`sourceGeneration`) | the readiness service's `readPlanningProjectionSourceGeneration(now)` → `readMembershipPlanningDerivationVersionKey(cache, nowMs)` (`membership-planning-version-key.js`, 250 ms latch keyed by `nowMs`) = versions of NODES, NODE_ENDPOINTS, SERVICES, PARTITIONS, CONTROL_PLANE_PUBLICATIONS, REPLICA_OPERATIONS | recomputed when the latch has expired for the caller's `nowMs`; **callers pass different clock domains** (planning owner: numeric `this.now()`; readiness paths: ISO `observedAt` → `Date.now()`; rebalancer: numeric pass-start `observedAt`) | `publishCompleted` (stamps `completed.sourceGeneration`), `canReuseCompletedSnapshot` (`matchesCompletedSourceGeneration`), every planning-layer memo |
| Rebuild admission / scheduling | `OwnerKeyReconcileQueue` (`owner-key-reconcile-queue.js`, maxConcurrency 1, maxItemsPerDrain 1, macrotask drain) | `enqueueBuild` per (ownerKey, buildOptionsKey) with reasons SOURCE_CHANGED / LIVE_VETO / TOKEN_ADVANCED_DURING_BUILD; pending items merge | `reconcile` |
| Rebuild | `reconcile` → `service.buildNodeReadinessSyncCurrent(ownerKey, {readinessPlanningOwnerBuild:true})` | one synchronous build per drain | — |
| Completed snapshot + status | `publishCompleted`: `{snapshot, capturedToken, buildOptionsKey, sourceGeneration (stamped at completion), tokenStatus CURRENT iff token unchanged since capture AND publication guard unchanged, completedAtMs, positiveDecisionLiveVeto}`; stored per (ownerKey, buildOptionsKey) | every reconcile; also bootstrap publish and rebase publish from `readSync` | `readSync` |
| Completed-snapshot reuse (generation currency) | `canReuseCompletedSnapshot` = ¬saturated ∧ same buildOptionsKey ∧ ((CURRENT ∧ exact token equal) ∨ **floored `sourceGeneration` equal to the current floored generation**) ∧ live veto unchanged (`capturePositiveDecisionLiveVeto`: evidence age > 30 s, lease expiry, heartbeat age > 30 s, local transport drift, publication guard) | evaluated per read | `readSync` → reuse, else `rebase` (node-table-only token advance) or `enqueueBuild(LIVE_VETO)` + **deferred contract** (`buildDeferredSnapshot`: all dimensions false, reason `planning_snapshot_refresh_pending`) |
| Supersession | implicit: a newer completed record replaces the older in `completedSnapshotsByOwnerAndBuildKey` (LRU of 16 option variants) | each publish | — |
| Consumers of the readiness contract | `CriticalTopologySettlingGate` (`unified-rebalancer-critical-topology-methods.js isCriticalNodeReady` → `getNodeReadinessSync(nodeId,{allowStaleOnCacheChange:false})` → dimension `controlPlaneRecoveryEligible`/`repairEligible`); routing (`Partition routing candidates filtered by readiness`, dimension `serveEligible`) | read-only | — |

Observed boundary property (from the code): exact-token reuse can only hold if NO covered table write happened between the build's capture and the read; under any churn only the floored path can admit reuse, and the floored generation is read through a latch whose `nowMs` argument comes from three clock domains.
