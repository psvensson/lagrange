## Minimal shared test seam

Add one small helper to the existing participant fixture, consumed by both selected tests: given a Promise and a unique local sentinel, use `Promise.race([operation, Promise.resolve(sentinel)])` directly and report whether the operation was already settled. The operation must be the first iterable entry; do not wrap it in another `.then` before the race. This gives a deterministic ECMAScript Promise-order observation: an already-settled operation wins, while a held operation loses immediately to the sentinel. It adds no timer, polling, tick, production state, private observer-map access or completion authority.

This seam is needed by two real controls:

1. recovery proves registry replacement/removal settles the old observer before the held membership read is released;
2. protocol proves malformed/conflicting joins return immediately instead of joining the starter Promise.

No other common helper is justified. The existing shared committed-membership gate, canonical request builder and registered route remain the facts/transport seams. Scheduler and cleanup-fault instrumentation is local to the actual-handler lifecycle test. Reentrant status movement is local to the controllable port's existing status fields and must not become a general fabricated-facts builder.
