## Owner diagnosis and smallest contract

Release completion remains `runCutoverAttempt` plus `releaseCensusDefect`; runtime queue/application/recorded progress remain Raft-runtime owned. ENABLE acknowledges the leader's durable origin application, not every member's application (`replica-handler-participant-release.js:64–72`; transaction request `:690–726`). Its next final census is immediate (`replica-handler-participant-cutover.js:279–297`). Sender delivery awaits enqueue acknowledgement; `enqueueStep` returns before the independently scheduled recipient drain (`raft-rs-runtime-owner.js:1705–1759,1877–1913`). Changing that acknowledgement to recipient application would couple Raft queues waiting on each other's sends.

Qualification: status reads do not await completion, but `readStatusObserved` can enqueue/start inbound work and return the last recorded observation (`runtime-owner.js:1392–1409`). Thus “INSPECT never drives inbound” is false. Preserve current read behavior. Existing origin ENTRY_COMMITTED is real (`partition-participant-transaction-apply.js:630–635`), but its afterCommit effects execute before runtime `recordAppliedEntry` and final `announce` publication (`application-transaction-owner.js:97–99`; runtime `:1089–1102,1174–1176,1228–1251`). A next-microtask assumption is not a publication guarantee. No current ordinary-entry publication wake exists: COMMIT is only an unused constant, excluded by the port EVENTS and RUNTIME_EVENT lists.

Choose **one post-ENABLE applied-position observation phase**, followed by the existing fresh final INSPECT batch and full classifier once. Do not choose a release-defect retry loop. The already exported `releaseFactsDefect` checks query state before origin (`release-contract.js:122–135`): EMPTY_LEGACY_SCHEMA can yield QUERY_DRAIN_PENDING even at drained 1/1/1 before control-origin application. Waiting on a selected defect subset either terminates too early or duplicates query semantics; old query proof can also be stale.

Preserve ordinary release/attempt/target/deadline fields; add `origin: enabled.origin`, using the exact existing canonical `{originIndex, originTerm}` from the ENABLE facts. ## Publication, lifetime and distributed behavior

Do not repurpose COMMIT, change MEMBERSHIP_CHANGED semantics or fan this wake through all current consensus-relay consumers. Map lifetime is bounded by hosted services, not message count. - Registry replacement/removal and existing leader/term/membership wakes trigger current-fact revalidation or cancellation.
