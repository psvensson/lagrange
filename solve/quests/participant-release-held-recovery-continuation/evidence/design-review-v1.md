## Consolidated correction batch

**R1 — reuse the existing fixed recovery observation cadence; do not add a second duration policy.** Design:43,68 currently accepts every safe nonnegative integer retryAfterMs and schedules `max(1000, retryAfterMs)`. A safe integer can exceed the platform timer range, and addition to now can lose safe integer precision. `RealTimeSource:44-45` delegates unchanged to platform setTimeout; existing retry owners explicitly recognize this boundary (`reconcile-queue-retry-ownership.js:106-111`; `readiness-planning-version-contract.js:181-187`). A virtual clock alone will miss platform overflow. Recommend simply reusing `BOUND.RECOVERY_RETRY_MS` for one later observation and **not consuming retryAfterMs at all**. `reconstructGroup:847-852` already enforces the runtime-owned not-before and persistence gate before entering the core, while `readStatusInRecovery:1369-1378` preserves single-flight. This keeps backpressure and both clock owners intact without copying a normalizer or introducing a timer constant. Pin one self-observation per 1000 ms, and prove high, invalid, boxed and accessor delay fields are irrelevant to scheduling because unused. If a different delay design is chosen, return it for review with the actual shared timing owner and real/virtual timer equivalence.

**R2 — extend the canonical final resume owner with the lifecycle fence.** The no-reopen-after-shutdown claim at design:71 is not implemented by existing source. `shutdownReplicaHandler:84,91-94` sets `handler.shuttingDown`, then waits for recovery while live services remain in the registry until :123. `resumeParticipantCutoverAdmission:63-79` can await facts and reopen the still-registered service without checking handler shutdown or service shutdown. The OPEN/idempotent branch :57-61 also lacks that lifecycle check. A check in recovery after awaiting cutover is too late to stop its admission mutation. Extend the file boundary to the canonical pause/resume owner; refuse resume through its existing typed outcome vocabulary if shutdown, retired service identity or service shutdown invalidates the attempt. Keep the existing term/configuration/generation checks and no-await final mutation. Preserve direct recovery shutdown's stop-and-settle semantics and specify how those differ from owning handler shutdown; do not fake a handler flag in a fixture. Pair actual handler shutdown during awaited release facts with service replacement during that await, plus the same exact live-state positive control. Root has explicitly selected canonical owner repair, not weakening the guarantee.

**R3 — specify ordered observation and multiple hosted-service semantics.** Design:42 promises both observation of every service and the old leader path unchanged; the current find at recovery:72-73 short-circuits at the first actual leader. Preserve current ordered leader selection and stop that selection once an actual leader is found. For a no-leader turn, every visited initialized current service is observed at most once and any canonical held observation retains exactly one partition-keyed debt. A healthy follower/candidate does not create debt; a mixture with a held service does. R1 removes cross-service duration arbitration entirely. State this explicitly and cover mixed held/ordinary services, a leader with another held hosted service, synchronous consensus reentry, and removal/replacement before the next due wake. Observed snapshots carry no permission and are discarded after the turn.

**R4 — define typed debt retention, discharge and background lifetime.** The retry template requires every debt stop to be attributable, and the current no-leader return at recovery:74 is silent. Specify the typed observation/decision rows for held-and-retained, ordinary nonleader/no-held, no initialized/current service, already-open, pre-origin/operator-required, unmeasured-build, cutover success/refusal, failed observation, removal, and stopped owner. Reuse canonical port classification and existing release outcomes; never infer success from absence. Report held identity and cause using the existing throttled reporter (:58-67), clear pending/report state when the last hosted service is removed, and avoid emitting per-read flood logs. A persistent typed hold is a background obligation bounded by the hosted service/handler lifetime, not a new operation with an invented deadline. Self turns are at most floor(T/1000)+1 per continuously held partition over T ms, plus real event nudges; maximum simultaneous release attempts remains four, pending debt is at most one per currently hosted partition, and unchanged-signature reports are at most floor(T/30000)+1. Runtime core attempts remain bounded by its own retry window, independently. Degenerate/unavailable observations and inability to register a wake must have an explicit owner stop/report rationale; do not quietly declare debt registered. Ordinary healthy followers remain event-driven.

**R5 — name the exact interaction/contract and proof changes.** Design:73,87 names only “the existing impact contract.” The current `raft-rs-runtime-application-transaction` contract/pair at impact-contracts:599-636,1515-1558 already registers the passive runtime witness but does not name release recovery/cutover or the final resume lifecycle seam. Name the existing contract that is extended, its live endpoints, the canonical source/contract decision table to be updated, and the two exact primary witness files. Update the runtime typed-status, recovery continuation, canonical lifecycle-resume owner and paired proof together. Preserve current release protocol/admission witnesses; regenerate metadata once at final freeze. If an extraction is needed, one adjacent owner module may carry the existing continuation, without introducing a second classifier/queue/cutover driver. No source-only semantic approval substitutes for this registry/contract obligation.

The file boundary extension required by R2 is a necessary current owner interaction correction, not absorption of snapshots, FreshMG, CDC, M1, W1 or C2. No deadline, concurrency or ratchet increase is acceptable.
