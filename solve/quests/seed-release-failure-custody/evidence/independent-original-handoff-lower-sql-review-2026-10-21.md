## The actual local sink fence

The bootstrap direct strategy first captures candidates by partition/table, then selects a Raft lane and, on a failed/thrown answer, loops through its captured candidate objects (`cdc-bootstrap-direct-sql.js:28-44,60-80,132-175`). The first failed local result throws, so not every candidate is necessarily dispatched during one observed fallback.

For an initialized target that admits the statement, `executeLocalQuery` calls `unreplicatedLocalMutationRefusal` before `runAdmittedPartitionStatement`, with no await between them (`partition-service-write-metrics-base.js:157-201`). The local admission owner reads that target's own generation row and returns UNREPLICATED_LOCAL_MUTATION whenever its origin is non-null; otherwise it checks cutover pause (`partition-local-mutation-admission.js:26-32`). The generation reader throws for missing/unreadable storage rather than returning an absent origin (`partition-participant-transaction-store.js:85-108`). Statement admission prepares/classifies; the actual admitted statement run is later (`partition-statement-admission.js:299-320,350-352`).

Thus an actual post-origin target cannot execute this local mutation merely because the CDC Raft answer was lost. The original error may nevertheless be replaced by the subsequent local refusal. That refusal is not evidence that the earlier append did not commit and cannot rearm an UNUSED birth right. CDC's terminal hop gate also preserves an uncertain prior hop if shutdown intervenes (`cdc-terminal-gate.js:79-104`); shutdown is not proof of nonapplication.

The existing test at `partition-participant-release-admission.test.js:44-49` binds this sink to a real local database and verifies zero inserted rows, but its origin is applied by the controllable-port fixture (`participant-transaction-fixture.js:416-450`). It is not an actual public/native lost-response witness. The note states this limit correctly.

## Required refinements for the future operation proof

- **Membership census is not the CDC candidate map.** Final release validates actual committed members and their matching applied origins (`partition-participant-release-contract.js:123-193`). CDC chooses objects from localPartitionServices. A stray, retired, replaced or newly added local object is not automatically a member covered by the earlier successful release. Bind the exact object/generation/origin of every captured fallback candidate; preserve that identity through the awaited Raft hop and prove the sink's own current check. No broad lock or new authority is prescribed by this review.
- **Keep actual dispatch separate from possible targets.** The first local refusal stops the fallback loop. A witness should positively record each actual fallback dispatch and its typed refusal, and separately record/justify the full selectable candidate extent. An assertion over an empty list or a single leader cannot stand in for the complete extent.
- **Lost-answer continuation differs by row owner.** Partition registration catches thrown INSERT errors and performs its read. Message-group registerReplica directly awaits INSERT at `message-group-service-row-owner.js:449-459`; a thrown error escapes before its result-based reconciliation. The note carefully names partition behavior, but a future common same-live guarantee must explicitly handle the message-group case and the actual CONFIG publication owner. It cannot assume all row owners already share the partition catch path.
- **Use the full exact original identity.** The new comparison must bind the original reserved birth/token/physical identity and required row fields, not merely a primary key, integer timestamp, or current-looking STOPPED row. Existing partition comparison and existing message-group comparison are not automatically the new grant contract. Any unavailable or conflicting authoritative read retains SUBMITTED; absence never authorizes a new INSERT.
- **Place response loss after an actual native commit.** The proposed witness must retain the real application/response identity and prove the SERVICES or reserved CONFIG mutation actually committed before withholding its response. Then require the real fallback to engage/refuse and the same live owner to resolve the exact row/value without a fresh INSERT. Count original invocation, actual lower submissions and attempted local runs separately. A committed-origin check alone is not proof that this subsequent row mutation committed.
- **Preserve distinct crash states.** Lost-before-send, lost-after-send and lost-after-commit all retain the specified consumed obligation. Cold SUBMITTED/TRANSFERRED remain the contract's HOLD without independent current authority; a same-live success cannot be reused as proof of cold mid-handoff progress. Cleanup and public nonserving fences remain separate requirements.

These are binding proof conditions and clarifications, not an instruction to introduce a second CDC writer, delete the fallback, add a generic retry layer, or alter current admission. No contradiction was found requiring correction of the frozen note's conditional conclusion. Its remaining public baseline, mutation/activation cut, ingress and issuance/abort prerequisites remain open. In particular this review does not resolve STOPPED versus activation in the sealed handoff scope.
