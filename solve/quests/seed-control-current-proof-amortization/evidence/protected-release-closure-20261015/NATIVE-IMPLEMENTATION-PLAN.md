## Findings and blockers, grouped by interaction

### Admission, concurrency and ownership

**G01 — No shared claim exists at both creation crossings.** Local command queueing can retain bytes across a Promise tail before core entry (S05/S06); forwarded MsgPropose enters through enqueueStep/step. A local-only check permits bypass; an ingress-only check misses local calls. The semantic release-bytes owner supplies one immutable classification; runtime owns one synchronous per-(partition, durable origin) M claim and physical-custody accounting. Distinct RA/RH/pure RETIRE cannot each obtain a slot. APPEND and supported committed replay must not be refused merely because the follower has local count debt.

**G02 — Existing release coalescing and OPEN fast return cannot represent closure intent.** S01's target-build join is weaker than exact request identity; S02 returns while D3 is OPEN and has no maintenance-availability event. The revised supplement explicitly makes CLOSING precede OPEN/build/control/drain, requires exact identity and a revision wake. That resolves the design placement observation, not the missing production implementation. Preserve original authorized intent across BUSY, subscribe then read/recheck revision, and never let a stale callback act on a replacement service/origin.

**G03 — The control-opening dependency would block closure if reused unchanged.** S01:269 awaits control CUT_OVER before PAUSE; its control helper requires query enforcement and successful release. The revised contract now puts retained-origin closure first. Witness must keep the control opener unavailable/drain-held while actual RH still closes the target partition; the same trace must retain the later opening refusal. Missing origin stays INIT/activation HOLD. Do not bypass control proof for opening to obtain this green.

**G04 — Producer authorization and D2 are different facts.** S03 is local capability authority, not replicated proof. The revised contract properly removes local WeakMap/boolean from D2. The eventual native ingress extension must bind the authorized producer, complete canonical M/K/partition/origin/kind and request form. Forwarding may carry immutable bytes, not recreate authorization. Actual D2 uses only committed-prefix facts. Activation/INIT and owner-proven provenance remain prerequisites; this report does not invent their proof.

### Recovery, transport and custody

**G05 — Waiter release, local absence, demotion and generic ACK are insufficient discard evidence.** S13/S14 intentionally forget pending answers while work may later apply. S09 has only index-range append diagnostics; S08 reconstructs native state but has no total occurrence census. An exact durable suffix replacement proves removal from that durable suffix, not removal from every other replica, native/Ready queue or delayed forwarded envelope. Only the runtime may combine exact owner evidence to close all possible custody. UNKNOWN is retained, never recast as an empty inventory.

**G06 — Pre-core acceptance and cold-process loss need an explicit discriminator.** If complete bytes existed only in a runtime object, same-process reconstruction and cold loss are not equivalent. Current fixture restart retains process state. Either retained bytes plus authoritative custody permit exact redrive, or the owner proves all copies discarded, or it reports unresolved/loud stop while safely closed. A new process cannot recover an unrecorded operator intent by assuming success or minting a new M. Full crash-progress remains conditional until its existing owners provide the necessary opening/transfer facts; no new durable ledger is approved here.

**G07 — Finite inbound service is missing and fairness cannot be shown with a reader that drives the queue.** S06:1691 consumes new arrivals until empty; each turn drains inbound before its command. S20's settle/deliverAll tick and S06's readStatus may drive pending inbound. A witness that manually drains/ticks after the critical cut point conceals starvation. The runtime change must capture finite work (selected contract: one owed tick and one accepted envelope, then M/H/settlement/ordinary), preserve all accepted remainder, check generation after waits, and maintain one owned wake. Ready host work also needs a finite-operation assumption; fixed number of Ready cycles is not a bound on a send Promise that never resolves.

### Application, result and encoding

**G08 — Correct atomic owner exists, but typed release effects do not.** S10 can atomically retire eligible rows, advance G, evaluate carried child on the actual prefix, write exact child result and parent receipt, change release state if accepted, and advance applied position. S11 currently has no such recognized command. A new source/test contract must specify the adapter, schema and error classes; an unknown-command failure is not the RH/RA semantic RED.

**G09 — Exact result replay needs explicit typed validation.** S12's statement replay is useful ownership precedent, not an implementation of release results. Validate commandKind, M, from/to G, K, content digest, original actual index/term and tagged conflict attribution; parent and child positions agree and are <= current applied watermark. Retired information is UNAVAILABLE, never proof of noncommit. Missing child with a matching receipt, divergent original positions, or corrupted bytes is a typed integrity HOLD. Replay must not allocate an annotation, use today's winner, or restore authority. Pure RETIRE has an explicit no-child tag; RH cannot alias RA.

**G10 — Canonical schema and position range require explicit implementation choices.** Proposed canonical arrays do not yet form the object-with-type consumed by S11. Define the exact native command wrapper and count all encoded UTF-8 bytes, including escaped strings/wrapper/domain-selected fields. Do not hash one set of fields and interpret another. Logical G/releaseVersion may be exact u64 decimal strings, but S07 and S12 do not presently support full-u64 native positions. Stay within the existing actual-position domain or obtain an explicit position-owner change and tests; no silent Number coercion, cap raise or wrap. Full max-encoding proof remains missing.

### Capacity and transaction boundary

**G11 — Both saturation witnesses must reach real legal histories.** RH uses the same M slot and future-child/receipt escrow as RA, not an extra emergency queue. C_H=4/Q_H=2 and C_A=8/Q_A=4 are illustrative active-leader projections. Full retained histories must be generated through the actual supported result path, not hand-inserted authoritative success rows. Pending old-generation entitlements survive retirement until applied/discarded. Claimed result bytes exclude native copies, follower backlog, full-log recovery allocation, WAL, snapshots and TX history. No broader memory bound follows.

**G12 — Retirement eligibility must survive the ordering interval.** The draft conditions progress on independent complete authority/TX/query bindings and rejects RETIREMENT_PINNED before new M admission. The eventual application also needs deterministic eligibility at actual prefix if obligations change after claim. A result cannot be erased while it remains the sole proof of an unresolved obligation. Required witness pairs closure progress with preservation/settlement of that obligation. If the source owners cannot make the dependency self-contained, state the pin/HOLD and its release event; do not hide it with an unsafe deletion or extra capacity lane.

**G13 — Whole-protocol readiness remains open.** RH alone does not fix the actual first-PREPARE boundary, ordinary-write binding, terminal replay identity, durable query discharge, COMMIT control, D3/D4 distinction, INIT, image/native Ready recovery or outer deadline handoff. TX1 stays local staging; a durable first PREPARE after HOLD is new admission. Existing PREPARED/terminal replay must be checked first under the transaction owner's full identity rules, and authoritative COMMIT/ROLLBACK decisions must settle while new admission remains closed. Known prior native findings stay attributed to their old bytes; none was rerun or silently waived.

## Proposed interfaces, explicitly not current production symbols

Use the current owners; the names below describe the minimum data contract rather than prescribe new classes. Do not export a traversable runtime/control object.

**I1 — Release bytes/admission adapter.** Input: typed kind PURE_RETIRE/RA/RH, partitionId, durable origin (index,term), fromG, immutable child bytes (kind/nonce/G/expected release tuple/D0 content or HOLD reason), producer-origin authorization context, and selected schema profile. Output: either typed pre-custody refusal or frozen canonical whole command, recomputed M/K/digests, immutable normalized fields, encoded byte counts and selected child-result class. Match interpreted fields to canonical contents. Any routing, deadline and service-generation metadata is separate and cannot retag contents. Native wrapper must be exactly specified and measured. Admission owner checks producer context before any proposal; forwarded shape validation delegates to the same bytes owner without granting new authority.

**I2 — `claimMaintenance`.** Runtime input: canonical whole command from I1, exact partition/durable-origin key, expected current lifecycle/runtime generation, local-versus-forwarded source for diagnostics, and an owner-fed coherent inventory revision derived from applied frontier/results plus native/Ready/durable/uncertain-forwarding custody. Synchronously before retaining bytes across an await, return exactly one of `{kind: 'CLAIMED'|'JOIN', ticket, revision}`, `{kind: 'RESULT', exactOriginalResult, revision}`, `{kind: 'HISTORY_RETIRED', historicalDisposition:'UNAVAILABLE', revision}`, or `{kind:'NOT_ADMITTED', reason, retryAfterMs?, revision}`; integrity/recovery holds remain distinguishable. `JOIN` requires exact bytes and identity, not same build. Ticket is runtime custody, not an application permission. Different M gets MAINTENANCE_BUSY, without durable refusal annotation. If inventory is unreconciled, reject new creation or hold a separately bounded and explicitly classified pre-admission envelope; do not call it a protected M opportunity yet.

The protected semantic claim is a reconciled active-leader admission. A nonleader may preserve bounded forwarding custody, but cannot announce that the remote leader granted M or use its stale local profile as the leader's permission. Both the leader-local command and an arriving forwarded creation ask the same leader-side claim. Sender-side unknown forwarding remains physical custody until authoritative resolution; the exact handoff is part of I3, not a second grant.

**I3 — Custody transfer/reconciliation.** Keep semantic M entitlement separate from physical occurrences. Before actual index exists, use an owned pre-core/forwarding token; after authoritative evidence exists, use exact `(partition, origin, M, index, term, digest, runtime/lifecycle generation)` for the relevant occurrence. Ready/store transfer must neither double-charge one transfer nor collapse two copies. Store's proposed postcommit append delta includes exact retained/removed entry identities and bytes/digests, old/new boundary, commit/applied boundary and transaction success. No delta is published on rollback. Runtime combines it with current core/Ready/forwarding facts; a store delta cannot assert global absence. Reconstruction receives authoritative image/frontier/results plus durable suffix and exact preserved transfers/current-term ordering evidence. New creation stays held on unreadable/incomplete/ambiguous facts. A supported committed prefix still applies on a follower with local credit debt.

**I4 — Atomic typed release application and result read.** S11 dispatches I1's verified immutable parent into S10's transaction using the *actual* committed index/term. Read the real predecessor prefix; perform deterministic retirement and child evaluation, save immutable original disposition/reason/winner and parent receipt, then applied state. Failure of any write rolls everything back; no afterCommit observer decides success. Reply/result read validates parent-child-frontier consistency and returns the historical outcome separately from current release authority and D3. The result owner owns persistence/replay/retirement; runtime merely consumes the applied occurrence charge after commit. Logical counters and actual positions have separately checked domains.

**I5 — Existing continuation + existing runtime round.** CLOSING installation is synchronous for the exact invocation/partition/origin, before an await or opening shortcut. Immediate D3 closure does not wait for control CUT_OVER. `maintenanceCustodyChanged(partitionId,origin,runtimeGeneration,revision)` is a wake, consumed via existing S02 enqueue. Subscribe then read/recheck revision to avoid BUSY/free-slot lost wake; unsubscribe/clear only this service's continuation on teardown. On every resume verify invocation, service object, origin, lifecycle and runtime generation. Finite runtime rounds capture eligible inbound/tick work without extending the captured set with later arrivals, then service admitted M/H/settlement/ordinary under existing budgets. Preserve accepted envelopes and their exact bytes in owned remainder; refuse new excess before ACK/custody. Do not insert another hidden scheduler or restore INSPECT loops.

**I6 — Existing TX1/write and image-owner dependencies.** Add immutable admission binding to existing session/seal/ordinary-write bytes owners and deterministic first-effect admission; full row replay precedes new-admission gating. Transaction DECISION remains transaction authority. Supported opening/image/native Ready owners must supply origin, coherent applied frontier, typed result/receipt image and tail provenance for I3. This report specifies that dependency only: no snapshot format, installer or diagnostic view gains authority here.
