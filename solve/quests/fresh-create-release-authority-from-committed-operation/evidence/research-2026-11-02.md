## 2. Mechanism, from source

1. **Issue.** `releaseFreshCreate` (`replica-handler-release-recovery.js:250-272`) asks `participantReleaseAuthorizationOwner.authorizeFreshCreate` (`participant-release-authorization-owner.js`) for a token.
   - The token is `Object.freeze(Object.create(null))`, registered in the module-level `AUTHORIZATION` WeakMap together with its issuing handler.
   - It is minted after the node-local create-admission read of the committed `replica_operations` row (`replica-create-admission-owner.js` `authorizeParticipantRelease`). Quest B adds a pending state for the case where that read is unavailable.
2. **Carry.** `completeParticipantRelease` calls `requestParticipantRelease` (`participant-release-client.js`). The first ask goes to `owner.nodeId`, the creating node itself.
   - When the local replica is not leader, the answer is `NOT_LEADER` with `leaderAddress`.
   - The client then asks the leader's node with the same payload, which includes the token.
   - A remote delivery is JSON-encoded (`message-router-delivery-encoding.js:76-77`). The frozen null-prototype token therefore arrives as `{}`: an object that is not in any `AUTHORIZATION` map.
3. **Validate.** `runCutoverAttempt` calls `localReleaseRefusal` (`replica-handler-participant-cutover.js:269-284`).
   - On the leader, a partition with **no write origin** (`readPartitionWriteOrigin(service.db) === null`) requires `participantReleaseAuthorizationOwner.validates(request.authorization, …)`.
   - On the leader's node, `AUTHORIZATION.get({})` is undefined, so the call answers `OPERATOR_REQUIRED{fresh_storage_or_operator_authority}`.
   - That outcome carries no `retryAfterMs`, so the completion loop ends and the create fails terminally.
4. **Consequence.** The authority of a fresh CREATE can only be checked on the node that issued it.
   - A brand-new partition whose first leader is not on the creating node refuses every non-leader founder's release until an origin exists.
   - The release that would create the origin must come from the leader's own founder. If that founder's create is itself still waiting (here it waited for a cohort whose other member had just been fenced), the group loses quorum.
   - The unavailability belongs to a fact (the founding create's authority), but it is answered as a permanent refusal.

**Rejected remedies on record that must not be reintroduced:**

- a `fresh: true` boolean in the request;
- treating a GENESIS request or stamp alone as fresh-storage proof;
- treating RESTART_CREATE or an existing-table lookup as authority;
- a new release-authority record (the job and operation are the durable record);
- automatic fresh permission for a restored legacy no-origin group;
- a second release algorithm or timer.

## 4. The committed fact that any leader could validate

Each founding CREATE of an initial table partition is a committed `replica_operations` row, written by the provisioning owner and the operation workflow. The row carries:

- **Identity:** `operation_id` (the deterministic intent `schema-job-…:operation:<nodeId>`), `type` ADD, `entity_type` partition, `entity_id`, `partition_id`, `replica_id`, `target_node_id`.
- **Durable create admission:** `create_admission_state` (ADMITTED → MATERIALIZED → ACTIVE, or FAILED/CLOSED), `create_admission_token`, `create_admission_attempt_token`, `create_admission_attempt_seq`, `create_admission_replica_created_at`, `create_admission_workflow_updated_at`. These are the fields that `rowMatchesAdmission` / `rowMatchesAdmissionIdentity` already check (`replica-create-admission-owner.js`).
- **Founding topology:** `steps_history[0]` carries `OPERATION_METADATA_KEY.BOOTSTRAP_MEMBERSHIP`, the GENESIS stamp of the founding cohort (founders and founder node ids). The provisioning owner writes it at `sql-query-engine-initial-partition-provisioning.js:588-649` before dispatch.
- **Terminal state:** `completed_at` / `workflow_step`.

**What a leader can decide from that row**, read authoritatively through its own create-admission owner's gateway (the same read quest B types):

- the row exists and matches the request's operation identity;
- it is an ADD of this partition;
- its admission is MATERIALIZED and not completed;
- its first step carries a GENESIS founding stamp whose founders include the leader's own replica identity, and every member of the leader's committed configuration is one of those founders.

Together these say: this no-origin group is the fresh founding of an operation the cluster committed, and its founding has not finished. That is the provisioning job identity the TX1 proposal named as the authority, read by whichever leader answers. It needs no in-memory token.

**What it must not grant:**

- A restored legacy group without an origin. Its founding operation is completed, or its configuration names non-founders: refused.
- An ordinary join ADD. Its first step carries a COMMITTED stamp, not GENESIS: refused.
- A RESTART_CREATE. It is not a MATERIALIZED founding: refused.
- In all three cases the answer stays `OPERATOR_REQUIRED{fresh_storage_or_operator_authority}`, and the explicit operator release remains available.
