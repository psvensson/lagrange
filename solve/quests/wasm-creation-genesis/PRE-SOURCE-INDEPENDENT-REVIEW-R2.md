## Resolution of the four blockers

**B1 — process custody: resolved at the contract level.** R2 explicitly changes the existing process-lock/shutdown/startup handoff. Failed shutdown retains exclusive ownership until actual process death; startup still attempts ordinary cleanups but does not release the final exclusive owner after any failed cleanup. Process death followed by retained restart is the selected failure recovery; no timer or speculative cleanup success releases the lock. This fits the existing owners without requiring a general retry scheduler. Preserve `awaitStartupAcquisition`'s await-before-abort ordering (`lagrange-runtime-startup.js:84–86`) and registration before abort assertion (`entrypoint-startup-acquisition-ledger.js:3–7`). A successful cleanup path must still release ownership.

**B2 — finite request history: resolved at the contract level.** The full request identity is now `(S, expected V, nonce)`, not an old installation ID accompanied by mutable expected-state context. The constructor returns complete canonical request bytes; the caller must durably retain them before delivery, and internal producers use durable operation intent. The ring stores one winning decision per closed V. Its winner gets its original exact result; a changed winning request conflicts; nonwinners all get the same refusal against that V's original winner. Retiring detailed history cannot make any old V current. No per-loser catalog row or separate tombstone stream is needed. Future/gapped pre-admission refusal is explicitly not a retained authoritative result. The API must not quietly construct a different K after UNKNOWN. This is the user's permitted concrete identity-field selection, not a new sequencing policy.

**B3 — resource attempt lifetime: resolved at the contract level.** Nine fixed slots retain ordinal fences. The original producer persists B and expected slot ordinal before reservation, then persists the returned token before dispatch; the receiver consumes that token and cannot mint an ordinal for an old CREATE. Lower ordinals become unavailable rather than fresh. Reuse requires exact CLOSED state and increments the ordinal. The all-nine-slots CAS also forbids duplicate live physical replica/storage/route identities, using canonical existing-owner identities. This closes the cross-slot loophole without relying on two local mutexes. CLOSED success or authoritative observation re-enqueues the existing reconcile owner; cache notification is only a wake. Required proof includes late original CREATE after reuse, competing slot reservations, lost reservation/release response and last-CLOSED wake without unrelated traffic.

The operation ledger remains the producer's existing custody owner, not the new arbitration authority. Its durable row must carry the specified immutable origin/token through recovery; `ServiceLifecycleManager._journalCreate` currently permits absent persistence (412–415), so implementation must not silently take that optional branch for this new route. This is a concrete implementation requirement already covered by R2, not a reason to reject the authorized extension.

**B4 — intact restart: resolved at the contract level.** R2 distinguishes common replicated genesis from receiver-local serving permission. A durable local PUBLISHED receipt permits the same outstanding resource to restart intact without live metadata; that global obligation continues holding J. Local RETIRED must be durable before global CLOSED, so once J can receive a serving grant, intact I cannot use the old permission. An ADMITTED-only resource can recover bootstrap, but cannot serve without resolving its grant. New CREATE must still obtain current binding/token. Source-local permission is excluded from copies/images. These are the missing paired rules needed to preserve the prior snapshot decision's intact-voter cold-restart guarantee without treating root identity as serving authority.

Crash ordering is essential: grant committed but local receipt absent must remain bootstrap-only; local RETIRED persisted but CLOSED response lost must resolve the original close without reopening; global CLOSED must never precede local retirement. C9's amended controls must demonstrate these cases with actual persistent state/process loss. Shared application-image/native-import remains held; no new installer or snapshot success is approved.
