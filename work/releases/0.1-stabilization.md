## Release Thesis

0.1 should prove internal coherence of the AGPL runtime, not parity with other
distributed SQL databases, dataflow engines, actor runtimes, or serverless
platforms.

The release is properly working only when the system can prove the core runtime
contracts that it already claims:

1. Tables and system metadata are durable through partition ownership.
2. Replicated partition writes do not expose uncommitted state.
3. Control-plane truth and projection state converge by bounded owner paths.
4. Distributed transaction recovery is durable, idempotent, and explicitly
   scoped.
5. Restart, rejoin, replica movement, publication convergence, and transaction
   retry/recovery are release gates, not local anecdotes.
6. Compute-near-data services are either hardened to the 0.1 promise or scoped
   out of the release claim.

## Non-Goals

0.1 does not need feature parity with CockroachDB, YugabyteDB, TiDB,
FoundationDB, Flink, Spark, Ray, Cloudflare Durable Objects, or any commercial
edition.

0.1 does not need to be a boring production drop-in database.

0.1 must not implement Pro or Enterprise features in this repository.

## Release Gates

The release gate set is intentionally smaller than the full roadmap. A gate can
close only with focused proof plus representative evidence or an explicit
narrower successor blocker.

| Gate | Minimum proof |
| --- | --- |
| Topology convergence | `rolling-restart` reaches active-gate coverage and publication projection convergence, or names a narrower owner boundary. |
| Committed side effects | Crash/restart during a proposed write cannot expose CDC or projection state for an uncommitted entry. |
| Transaction recovery | Prepared and in-flight distributed transactions recover to committed, aborted, or retryable terminal outcomes after restart. |
| Replica movement | Replica movement and handoff produce no hidden drops, duplicate owner writes, or stale serving routes. |
| Integrated failure matrix | The named failure-gate matrix has executed artifacts, not only a checklist. |
| Compute runtime, if in scope | Service lifecycle, dispatch, and resource limits have focused proof and a release-scoped isolation statement. |

## Update Rules

Update this program when one of these changes:

1. A release gate is added, removed, closed, or narrowed.
2. The 0.1 release thesis or non-goal changes.
3. A track consumed by this release is added, split, closed, or declared out of
   scope.
4. Representative evidence changes the release-level risk, not just a package
   counter, node id, timestamp, or artifact filename.

Do not update this program for ordinary package progress. Record ordinary
progress in the active package and the relevant sprint. Record track-level
invariant movement in the relevant track file.
