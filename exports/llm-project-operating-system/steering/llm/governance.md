# Governance Steering Pack

Load for roadmap, package, and closure checks.

## Rules

1. Ideas live under `work/ideas/`.
2. Active implementation lives under `work/packages/active-YYYYMMDD-slug.md`.
3. Broad or scope-changing ideas sharpen `roadmap.md` before implementation.
4. Direct packages are allowed for bounded work inside approved scope.
5. Sprint files may group packages but do not replace them.
6. At most one active package should own the same representative boundary.
7. Parallel package work needs disjoint file, owner, and proof scope.
8. Completed packages are renamed to `done-...`.
9. Superseded packages are renamed to `superseded-...` and link successors.
10. Closure proof is not invented after the fact.
11. Focused package slices are committed and pushed before the next slice.
12. Roadmap status must match package and validation evidence.
13. If implementation proves roadmap status overstated, correct the roadmap
    with the package closure.
