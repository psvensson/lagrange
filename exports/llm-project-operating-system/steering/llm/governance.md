# Governance Steering Pack

Load for roadmap, implementation, and closure checks.

## Rules

1. Legacy work-package templates live under `_legacy_work/work/` for reference only.
2. Active implementation uses the target repository's current workflow.
3. Broad or scope-changing ideas sharpen `roadmap.md` before implementation.
4. Direct implementation slices are allowed for bounded work inside approved scope.
5. Planning files may group implementation slices but do not replace live evidence.
6. At most one active slice should own the same representative boundary.
7. Parallel work needs disjoint file, owner, and proof scope.
8. Completed work is closed only with live proof.
9. Superseded work links successors.
10. Closure proof is not invented after the fact.
11. Focused slices are committed and pushed before the next slice.
12. Roadmap status must match implementation and validation evidence.
13. If implementation proves roadmap status overstated, correct the roadmap
    with the package closure.
