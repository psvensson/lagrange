# LLM Project Operating System

A portable, domain-neutral **way of working** for non-trivial projects driven by
LLM agents. Extracted from a production codebase and generalized so it can seed a
new repository directly.

It bundles five things that reinforce each other:

1. **Steering doctrine** (`steering/`) — compact, always-loaded rule packs plus
   their canonical sources, regenerated by a deterministic pack generator.
2. **The Quest/Solver engine** (`tooling/solve.js`, `tooling/solve/`) — work is a
   sealed Quest with a `doneWhen`; the Solver records measured attempts,
   findings, and a terminal SOLVED/EXHAUSTED report. No goalpost-moving.
3. **The closure-ledger grammar** (`ledger/`) — debug hard, distributed, or
   intermittent failures one violated invariant at a time, with a stable witness.
4. **Subagent delegation + verification** (`steering/workflow/subagents.md`) —
   delegate focused work; independently verify a change before relying on it.
5. **A validator/guardrail gate** (`tooling/validators/`, `.githooks/`) —
   complexity, cycles, duplication, file-size, naming, and steering-drift checks
   enforced at commit/push and (optionally) in CI.

> **Kernel vs. example.** Files banner-marked `Method kernel` are the portable,
> domain-neutral mechanism — keep them and extend them with your project's own
> rules (the four `steering/{system-guidelines,runtime-contracts,architecture,
> roadmap}.md` files are domain-neutral baselines in this category). Files
> banner-marked `EXAMPLE` carry illustrative placeholder content you **replace** —
> `ledger/records/CL-000.example.md` and the `*.template.md` files
> (`governance/edition-matrix.template.md`, `architecture/contract-record.template.md`).

## Apply to a new repo (60 seconds)

```bash
node apply.js /path/to/your/repo     # copies bundle, merges scripts, wires hooks
cd /path/to/your/repo
npm install                          # pulls validator devDependencies
npm run steering:llm:pack            # regenerate the compact packs
node tooling/solve.js new --id my-first-quest
```

`apply.js` copies the bundle into the target repo root, places the git hooks at
`.githooks/`, merges the `scripts` + `devDependencies` from
`tooling/package.scripts.json` into the target `package.json`, and runs
`hooks:install` (`git config core.hooksPath .githooks`). It will not overwrite
existing files unless you pass `--force`.

## Layout

| Path | What |
| --- | --- |
| `AGENTS.md` | Single entry point + steering load order. Read this first. |
| `steering/` | Source doctrine (`.md`) + `packs/` (compiled) + `pack.config.json`. |
| `steering/packs/` | Always-load compact rule packs: core, architecture, testing, style, governance + `rules.json`. **Generated — do not hand-edit.** |
| `ledger/` | `closure-grammar.md` + `records/CL-###.md` + `INDEX.md`. |
| `tooling/solve.js`, `tooling/solve/` | The Quest/Solver engine (Node stdlib only). |
| `tooling/steering-pack/generate.js` | The pack generator. |
| `tooling/validators/` | The full checker family + `check-TEMPLATE.js`. |
| `tooling/hooks/` | `install.js` + the `githooks/` payload (pre-commit, pre-push). |
| `solve/` | The Quest store (created on first `solve new`; layout in `docs/quest-store.md`). |
| `governance/` | `edition-matrix.template.md` + `scope-discipline.md`. |
| `ci/` | Sample CI workflow mirroring the local hook gate. |
| `.claude/` | Minimal Claude Code settings + memory convention. |

## What you must add for your project

The bundle is dependency-light, but a few checks need config/devDeps the bundle
deliberately does not pin to one toolchain:

- **devDependencies** (merged by `apply.js`, installed by `npm install`):
  `eslint`, `knip`, `madge`, `dependency-cruiser`. The Solver engine, the pack
  generator, the hooks, and the **node-only validators** (complexity,
  cognitive-complexity, file-size, constant-names, duplication, `guideline:*`)
  need none of these.
- **Config files** you provide: `knip` (for `test:unused`), `eslint.config.js`
  (for `lint`), and `dependency-cruiser.config.cjs` (for `test:deps`). Until
  these exist, those three scripts fail; the rest of the gate works standalone.
- **Replace the EXAMPLE files** — fill `steering/{system-guidelines,
  runtime-contracts,architecture,roadmap}.md` with your project's real doctrine,
  then `npm run steering:llm:pack` to recompile, and edit
  `governance/edition-matrix.template.md` for your scope.
