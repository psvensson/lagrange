# Maintaining Capability Documentation

Human implementation status has one rendered entry point:
`docs/current-capabilities-and-limitations.md`.

Its inputs are:

- `docs/current-capabilities.json` for cross-system product facts; and
- `docs/service-portability-capabilities.json` for runtime portability.

Regenerate after changing either input:

```sh
npm run docs:capabilities:generate
```

Validate that configuration defaults, ports, probes, PostgreSQL modes,
lifecycle SQL, architecture limitations, Helm probes, and generated bytes still
agree:

```sh
npm run audit:current-capabilities
```

The rendered page contains product facts only. Do not put development workflow,
evidence locations, automation instructions, or agent guidance in it. Add
maintenance instructions here and keep implementation rules in their existing
development or steering owner.

Capability entries record the live production status rather than file presence:
for example, `messageGroupLogCompaction` remains `"unsupported"` even though
partition snapshot compaction (`SN1`) is active on `raft-rs`, and OCI
`managedExecution` remains `"unsupported"` even though descriptor and scaffold
modules exist.
