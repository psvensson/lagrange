## 3. Work completed

### Execution and evidence ownership

The candidate removes retry/reassignment and last-green behavior from the
reviewed publication/placement path. Each admitted attempt retains its own
outcome and evidence. Missing declared preparation producers refuse execution.
The exact gate materializer owns cancellation through the real child scope,
preserves the first failure or signal, and uses bounded close/absence checks.
Git cleanup refusal retains the registered checkout; recursive deletion and
prune-after-refusal are removed from the corrected cleanup owners.

Placement now admits its script, logs, list and bundle exclusively. After
wrapper admission, failed, unavailable or interrupted attempts retain the
artifacts actually acquired: checkout, source identity, TAP, ref, list, bundle
and controller inputs as applicable. Failure before wrapper acquisition can
release that attempt's owned inputs. A remote BUSY refusal may have only an
uploaded bundle; it does not imply a checkout, ref, list or TAP was created.
The generated shell distinguishes the direct shell, waiter and owned group. Its existing
abort budget contains one TERM stage and one forced-closure stage; repeated
signals do not renew that budget. Clean closed execution may remove its own
checkout once through Git. No sibling cleanup sweep is introduced.

Shared process helpers signal only an acquired process group, without a
direct-PID substitute. Capture success waits for output close, including late
bytes after direct exit. An expired capture deadline reports incomplete output
and unconfirmed group closure rather than calling a signal a closed scope.
Failed spawn releases its deadline. Formation holds own detached groups,
preserve loss after HELD, and cache their release outcome. Harness cleanup
attempts all acquired releases and retains the exact earlier failure when
later finalizers also fail.

Parallel placement requires its named controller-child collaborator before
any admission. The candidate's finite shared fixture explicitly supplies that
contract. It is not a proof of process lifetime. The original fixture remains
immutable in the original measurement lineages.

### Publisher and proof receipts

The publisher's exact-head and post-merge planning paths use the canonical
strict remover. Failed or uncertain acquisition keeps the attempted path.
Cleanup-only failure is adverse; an earlier execution error remains primary.
If a push and publication receipt have already been verified, a later cleanup
error explicitly carries and reports that published result. It never claims
the push was undone.

Identity-reusable release receipts must carry the current identity algorithm
and a valid digest, including at exact lookup. An identity ref or checkout
cannot lend missing identity data to an old receipt. Indexing a valid receipt
whose identity ref is absent remains supported. Historical objects and refs
are retained. Exact-only corpus receipts remain intentionally identity-free.
Their separate execution-envelope applicability gap is still open.

## 6. Open source findings to resolve first

### Receipt without an execution envelope

The current receipt reader still accepts a receipt created before execution
reports existed. The existing `proof-receipt-execution-report.test.js` explicitly
expects that historical success. This is distinct from intentionally
identity-free corpus receipts.

Current `validatedExecution` always produces an envelope containing a
SHA-256 report digest, producer attribution, and summary fields for planned,
executed, assertions, runs, commands, reused proofs and passed-on-retry. The
reader currently does not require that envelope. History `207d4f792` and the
sealed `proof-receipt-bound-to-validated-execution` Quest explain the old
decision; the owner's current no-legacy instruction supersedes current
applicability, while historical evidence remains immutable.

Next: add original-compatible real-tag/ref refusal controls in the existing
root, measure the original behavior on a physical lab, and require the current
execution envelope at read/lookup/index. Preserve original objects and refs.
Keep valid identity-free corpus receipts and valid release receipts that cite
an exact corpus proof. A cited release can legitimately have zero direct
files/runs/assertions: do not impose blanket positive-count checks or pretend
a summary replays the native report. No controls or correction for this gap
have yet been authored in the frozen candidate.

### Catch-driven process observation

`isLocalCorpusProcess` still catches any `/proc/<pid>/cmdline` read failure and
launches `ps` as an alternate observer; reconciliation converts false to LOST.
The path originated in `b0ceb7024`. It does not kill a process. Existing
live/reused-PID/zombie controls do not measure this alternate path.

Next: define one observation method per supported platform, and distinguish
unavailable observation from confirmed absence. Do not infer process death
from inability to inspect it. Native macOS runners are documented, so silently
declaring the entire project Linux-only would be wrong. No implementation or
new physical measurement for this boundary is in the frozen candidate.

### Additional source-review caution

Some existing publisher/session/proof Git helpers inherit ambient repository
pointers; the normal test runner strips them. This predates the new strict
cleanup call and is not a demonstrated regression of that change. If extending
those APIs to hook contexts, trace the actual canonical environment owner and
