Colocated Shard Topology & Distribution-Key Faithfulness

Citus distributed tables require explicit distribution keys and colocation groups to execute without cross-worker hops:

  • Account colocation: accounts and account_history share distribution key account_id (colocate_with => 'accounts').
  • Merchant colocation: merchants and merchant_history use distribution key merchant_id (colocate_with => 'merchants').
  • Device colocation: devices and device_history use distribution key device_id (colocate_with => 'devices').
  • Sharded SQL vs UDF: evaluating coordinator routing in citus-sql-service against worker shard pushdown in citus-distributed-function.

Entity-Locality Progression (create_distributed_function vs Lagrange)

Progression across 4 graph shapes showing single-locality and cross-entity scaling:

  • Local-only control: citus-distributed-function routes directly to the shard worker, collapsing multi-statement round-trips.
  • Cross-entity fan-out: As stages span remote entities, Citus incurs inter-worker hops.
  • Lagrange native actor state: Lagrange native actor state colocates execution directly with partition consensus; comparative performance claims await admitted GCP/lab measurements.
